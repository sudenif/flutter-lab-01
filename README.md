## Запуск

Нужен Flutter SDK с Dart >= 3.10. Исходная реализация подготовлена на Flutter 3.47.9 / Dart 3.13.7; точные разрешенные зависимости находятся в `pubspec.lock`.
Установите SDK и добавьте `flutter/bin` в PATH. Для Windows нужны Visual Studio Build Tools с C++; для Web — браузер Chrome или Edge.
Клонируйте проект в путь без кириллицы, например `C:/projects/flutter-lab-01`.

```powershell
flutter pub get
flutter run -d windows
# или Web
flutter run -d chrome
```

Стандартная точка входа — `lib/main.dart`. В VS Code также есть одна конфигурация Run and Debug именно для этой работы.
На Windows для папки с кириллицей можно использовать `./run-lab.ps1`: скрипт создает короткую ASCII-ссылку, печатает Project build path и запускает только этот этап.
Если PowerShell блокирует ps1, используйте стандартные команды Flutter из ASCII-пути; изменять политику выполнения не требуется.

Именованная точка входа из отчета сохранена: `lib/main_lab1.dart`. Файл `main.dart` вызывает ее. Других учебных этапов здесь нет.

## Проверки

```powershell
flutter analyze
flutter test --reporter expanded
flutter test integration_test/app_test.dart -d windows
flutter build web --release --no-wasm-dry-run
```

Нативный интеграционный тест относится только к этому этапу. Он проверяет реальное окно Flutter и сохраняет настоящие кадры в `test_screenshots/`; эта папка и сборочные кэши исключены из Git.
Тесты репозитория и BLoC, когда они есть, используют управляемые ответы для воспроизводимой проверки ошибок. Проверка HTTP в нативном тесте использует настоящий Dio.

Результаты проверки выделенного проекта записаны в `verification/`. Исходные исторические снимки в отчете и дополнительные материалы относятся к общему учебному проекту; подписи, показывающие будущие этапы, сохранены явно.
